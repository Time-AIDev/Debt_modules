0. Plain language first

Discovery — connecting to Odoo and listing which models hold data before assuming a mapping. Snapshot — the last good copy of Odoo data kept on disk so the app runs when Odoo is down. Helpdesk ticket — the Odoo record CX opens when a customer reports a fault; the team pastes its link into the sheet today.

1. What stands from v1.1

JSON-RPC over HTTPS, read-only always; ODOO_URL, ODOO_DB, ODOO_LOGIN, ODOO_API_KEY in backend/.env, names in code, values nowhere; discovery first; sync on demand plus a guarded startup attempt; the fallback chain ODOO → cached snapshot → sheet fixtures with data_source on every row; masking of phone and email at import; local status overrides with provenance (R14). Nothing here changes those.

3. The gap list

For every order whose actual installation end date is set and whose status is not Order-Done, Debt lists the order, the crew, the dates and the days since installation. The list is shown on Data sources and migration for the operations owner. Debt does not flip the status; it says who should.

4. Failure modes

Unchanged: not configured → 422 integration_not_configured naming the variable names; unreachable → 502 integration_unavailable, retryable; a corrupt snapshot reads as no snapshot. New: a model missing from discovery marks that read as UNAVAILABLE on the status panel, and every screen that depends on it says so in place rather than showing an empty gate as passed.
