0. Plain language first

Draft — a document that exists in PEAK but is not yet in the books; PEAK shows it in its draft list and a person approves it. Approved — in the books; it now has a document number and, for an invoice, a QR code. Rejected — a person in PEAK declined it; PEAK keeps the reason. Instance — one PEAK company file; there are two, EPC and SPV. Idempotency key — a unique tag Debt stores before creating a draft so a retry never creates it twice; PEAK bills per create.

1. The rule

Debt creates drafts and reads state. Debt never approves, posts, updates or deletes a PEAK document, and never edits an approved one — a change is a new draft (an amendment or a credit note) that a person approves. The client has two verbs and a test asserts there is no third. Nothing in this document changes who approves: AR does, inside PEAK.

2. The document record

peak_document: uid, intent (one of the 23 rows below), entity and company_id, source_ref (the invoice, receipt, restructure, recovery case or cancellation it came from), payload as sent, idempotency_key (stored before the call), state PENDING → DRAFT_CREATED → APPROVED_IN_PEAK or REJECTED, or UNSENT on a transport failure; peak_ref and peak_number once known; qr_payload once approved (invoices only); rejection_reason; created_by and timestamps. A replay with the same key returns the existing record. UNSENT is a queue on the Payments and PEAK drafts screen and is re-sendable.

4. Read-back

State is read on demand from the document card, in the 02:30 run, and by webhook when PEAK provides one. APPROVED_IN_PEAK carries the PEAK number and, for invoices, the QR payload that the delivery step needs. REJECTED carries PEAK's reason and raises a tier-6 Today item for the person who raised the document. Whether PEAK's API exposes draft state for read-back is INT-05, confirmed on first live contact; until then the prototype's stub models both answers and the screen shows "state unknown — check PEAK" rather than guessing.

5. Credentials and instances

PEAK_UAT_CONNECT_ID, PEAK_UAT_PASSWORD, PEAK_UAT_USER_TOKEN and optional PEAK_UAT_BASE_URL as before; a second set with the suffix _SPV is read when present (INT-06). Names in code and refusals, values nowhere. /readyz reports configured-or-not only.

6. Failure modes

Not configured → 422 integration_not_configured. Transport failure → the document is UNSENT, re-sendable, 502 peak_unsent. Same key replayed → the existing record, never a second create. Any attempt to approve, update or delete through Debt → 403 peak_draft_only; the endpoint does not exist and the client has no method, so this code appears only from a mis-wired router in tests.
